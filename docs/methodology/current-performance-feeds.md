# Current tennis performance feeds

The frozen Sackmann archive remains the historical baseline. Current serve/return counts are refreshed separately, before every `/tennis` forecast and by the existing four-hour daily-slate workflow:

- ATP: [TennisMyLife's current-season, qualifying and ongoing-event CSVs](https://stats.tennismylife.org/tennis-match-database). These use ATP player identifiers, which are **not** Sackmann player identifiers.
- WTA: the official site’s [tournament calendar](https://api.wtatennis.com/tennis/tournaments/) and completed-match statistics at `tournaments/{event}/{year}/matches/{match}/stats`. The field mappings follow the official site's service/return statistics, including first/second serve counts and the opponent's break-point opportunities.

Only validated completed singles counts are used. Names must resolve to one established model identity; winner-oriented set scores and format must match an existing result; tournament names or venues must agree; dates must agree (within one day for WTA timestamps or the tournament's 14-day window for ATP week-level dates). More than one candidate in either direction is rejected. No new matches, winners or identities are added by this adapter. Retirements, walkovers, incomplete matches, impossible counts and unavailable statistics are excluded. Existing usable historical statistics are retained. Official current-edition WTA metadata resolves surfaces only on an unambiguous tournament name or city and active edition dates.

Provider counts live in `data/live_stats/`, excluded from commits and site publication. Follow the providers' applicable usage terms. GitHub Actions caches are updated under a unique key per run, so a static immutable cache cannot pin the first downloaded version forever. Current WTA records are refreshed again if the provider updates their version; failed downloads retain the last good records. Missing coverage is reported rather than fabricated. `docs/data/performance-health.json` contains source status, actual newest matched-statistics dates, join counts and revisions, without raw per-match statistics.

The global performance cutoff advances only when validated counts join to an actual recorded match. It does not use the download timestamp. Explicit historical `asof` builds exclude same-day/future results and their statistics. A performance revision is hashed into frozen inputs; newly attached counts trigger a new version only before scheduled play. Earlier frozen forecasts remain unchanged.

The >50% probability, positive fee-inclusive EV, Monte Carlo error and per-player data-quality gates remain in place. Restoring coverage does not guarantee profitable bets or establish a measured accuracy improvement. Some events have no usable performance statistics; those matches can still return NO BET.

Validation: offline tests cover count bounds, winner orientation, provider identity, exact/ambiguous result joins, wrong scores/dates/formats, source errors, missing/repeating pagination, cache persistence, historical cutoffs, revision changes and surface conflicts. Live local validation on November 2 joined over a thousand ATP and thousands of WTA completed results to fresh performance counts without changing result populations. Both tours' last valid performance dates were November 1 or later. Coefficients were not retuned to the Maria–Andreescu outcome.
